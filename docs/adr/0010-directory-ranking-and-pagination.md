# Directory browse ranking and pagination

Empty-query Instant Directory and Category Pages need a stable, editorial order as the catalog grows past a single screen. We require curated **`directory_global_rank`** (Home All) and **`directory_category_rank`** (Category Pages and Home category chips) on every Service — lower integer = higher. Ties break by Display Name A–Z. Non-empty Instant Directory search keeps score order (ADR-0007). Lists paginate at **20** cards per page, but if the full result set has **≤ 21** items we show all (no lonely one-card page). When paginating, a brand-green **Load more** control sits between the grid and the numbered pager: it **appends** the next batch (viewport stays put; focus moves to the first new card). Numbered pages / Prev / Next **replace** the visible list and scroll to the results top. Count line recalculates (`Showing` + `Page N of M`). The numbered pager uses an **ellipsis window** (`buildPageWindow`: first/last + ±1 around current; show all pages only when ≤7) so long catalogs stay compact. Pager and Load more use brand **`--green`**, not Category accents. We rejected analytics-driven popularity, a single shared rank field, shareable `?page=` Category routes, Load-more-only (no pager), growing page size on page 1, and rendering every page number for long lists.
